## 1. 유저와 기회 짚기

**타겟 유저**
- **현재 유저**: 러비더비에서 AI 캐릭터와 텍스트로 관계를 쌓아온 유저. 이들의 핵심 니즈는 "관계가 더 진짜 같았으면"이다. 텍스트 채팅은 몰입의 상한이 낮다 — 목소리도, 얼굴도, 함께한 '기록'도 없다.
- **잠재 유저**: 인스타 릴스에서 인생네컷·AI 콘텐츠를 소비하는 10~20대. 이들은 앱을 검색해서 오지 않는다. **친구의 피드에서 본 결과물**이 유입 경로다.

**페인 포인트**
1. 기존 AI 화상채팅 서비스(lemonslice, talkpersona 등)를 직접 써본 결과: **응답 딜레이가 크고, 목소리 선택지가 없으며**, 일부는 선정성에 치우쳐 '관계' 감성이 없다.
2. AI 연인과의 관계는 **밖으로 꺼낼 수 있는 산출물이 없다.** 커플은 인생네컷을 찍는데, AI 연인과는 남길 것이 없다 → 공유가 없으니 바이럴도 없다.

**왜 이 유저인가**: 러비더비의 성장 병목은 신규 유저 확보(과제 예시 주제 #6)이고, 기존 유저의 리텐션 동력은 감정적 몰입이다. 두 문제를 하나의 루프로 풀 수 있는 유저 접점이 바로 이 지점이다.

## 2. 서비스 기획

**가설**
> AI 연인과의 관계에 ①실시간 음성 대화(몰입)와 ②공유 가능한 시각적 기록(바이럴)을 더하면, 기존 유저의 세션 깊이가 늘고 신규 유저가 릴스를 타고 유입된다.

**핵심 경험 — 하나의 루프**
```
📞 AI 영상통화 (관계를 깊게)          📸 AI 인생네컷 (관계를 밖으로)
  음성으로 실시간 대화             →    통화 말미에 AI가 먼저 제안:
  얼굴을 보며 통화하는 감각              "우리 오늘 기념으로 네컷 찍을까?"
                                   →    셀피 + AI 연인 합성 4컷 생성
                                   →    저장 → 릴스 공유 → 신규 유저 유입 → 📞
```
전체를 다 설계하기보다 이 루프의 최소 단위 — **통화 → 제안 → 네컷 → 공유** — 하나에 집중했다.

**목표 (성공 신호)**
| 단계 | 지표 | 성공 기준(가설 검증선) |
|---|---|---|
| 몰입 | 통화당 평균 유저 발화 턴 수 | ≥ 6턴 (텍스트 채팅 대비 세션 깊이) |
| 전환 | 통화 → 네컷 진입률 | ≥ 30% (AI의 제안이 동작하는가) |
| 바이럴 | 네컷 생성 → 저장/공유율 | ≥ 50% (결과물이 올리고 싶은 퀄리티인가) |
- 계측: **Vercel Analytics** 연동(방문·경로), 다음 단계로 커스텀 이벤트 추가.

## 3. PoC

**제작물** — 실제 동작하는 모바일 웹앱 (Vercel 배포)
| 구성 | 구현 |
|---|---|
| AI 영상통화 | 브라우저 음성인식(STT, ko-KR) → **Vercel 서버리스 함수 → Claude API(`claude-opus-4-8`) 실시간 응답** → 음성합성(TTS)으로 캐릭터가 말함. 대화는 스크립트가 아니라 매 턴 LLM이 생성. 페르소나(4종)는 시스템 프롬프트로 제어. |
| AI 연인 캐릭터 | Higgsfield(Soul v2)로 생성한 실사풍 캐릭터 4종 |
| 인생네컷 | Canvas API로 온디바이스 합성 — 셀피+캐릭터 2분할 4컷, 컨셉별 색감/필터/스티커, PNG 저장 + Web Share API 공유 |
| 응답 지연 대응 | 리서치에서 확인한 기존 서비스의 딜레이 단점 → 짧은 발화 강제(max_tokens 300, effort low) + 통화 UI의 '생각 중' 상태 표기로 체감 지연 완화 |

**도구**: Claude Code로 전체 개발 · Anthropic SDK · Higgsfield MCP(캐릭터 생성) · Vercel(배포+Analytics)

**핵심 인터랙션 (이 PoC로 확인하려는 것)**
1. **음성 왕복 대화가 '통화'로 느껴지는가** — STT→LLM→TTS 왕복 지연이 관계 몰입을 깨지 않는 수준인지.
2. **AI의 네컷 제안이 전환을 만드는가** — 대화 맥락에서 AI가 먼저 "네컷 찍자"고 제안했을 때 유저가 따라오는지(통화 4턴 이후 CTA 노출 + 프롬프트 유도).
3. **결과물이 공유 욕구를 만드는가** — 4컷 프레임의 퀄리티가 '릴스에 올릴 만한' 수준인지.

## 4. 본인의 판단

**AI가 한 부분 / 내가 판단한 부분의 경계**
- AI(Claude Code, Higgsfield)가 한 것: 코드 작성, 캐릭터 이미지 생성, 통화 대사 실시간 생성.
- 내가 판단한 것: **두 아이디어(화상채팅·인생네컷)를 별개 서비스가 아니라 하나의 루프로 묶는 결정**, 타겟·가설·지표 설계, 기존 서비스 리서치에서 '딜레이·목소리'를 핵심 단점으로 규정하고 PoC 설계에 반영한 것, 네컷 합성을 이미지 생성 API 대신 온디바이스 캔버스로 처리해 비용 0·지연 0으로 만든 트레이드오프.

**가장 자신 있는 포인트**
- 통화(리텐션)와 네컷(획득)을 **하나의 성장 루프**로 연결한 구조. 각각은 흔한 아이디어지만, "통화 중 AI가 네컷을 제안한다"는 연결이 이 기획의 차별점이다.

**더 검증이 필요한 부분**
- 음성 왕복 지연의 실제 체감(네트워크·기기 편차) — 스트리밍 TTS·부분 응답 재생으로 개선 여지.
- 네컷의 '진짜 함께 찍은 느낌' — 현재는 2분할 합성. 다음 단계는 이미지 생성 모델로 두 인물을 한 장면에 자연스럽게 합성(비용·안전성 검토 필요).
- 실사풍 AI 연인의 초상권·딥페이크 리스크 가드레일.
